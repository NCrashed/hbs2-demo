== 2. The owner publishes a project ==
An ordinary git repository, pushed to an hbs23:// remote. The remote's
key is the project's identity from now on.

[owner]
$ git init -q
$ printf "#!/bin/sh\necho \"Helo, \$1\"\n" > greet.sh && cat greet.sh
#!/bin/sh
echo "Helo, $1"
$ git add greet.sh && git commit -qm "greeter: first version"
$ hbs2-git3 repo:init --new
added git remote normal-empty hbs23://7gGDvjZ6x4Dvq2DuK1FRLsRnpmjnge94wyMKozyxb6wi
repo:init names the remote with two random words; call it origin.
$ git remote rename "$(git remote | head -1)" origin
$ git push -q origin master
use git fetch to get latest versions
repo key: 7gGDvjZ6x4Dvq2DuK1FRLsRnpmjnge94wyMKozyxb6wi

== 3. The owner opens the project to contributions ==
Contributors do not get accounts. They write letters to the project's
mailbox, and the owner decides what becomes part of the record.
The mailbox has a key of its own, and a sigil: the public half people
encrypt their letters to.
$ hbs2-cli hbs2:keyring:new > ~/mailbox.key && mkdir -p ~/.hbs2-keyman/keys && cp ~/mailbox.key ~/.hbs2-keyman/keys/ && hbs2-keyman update
$ hbs2-peer mailbox create --key $MBOX hub
created 6kc1AzwUCeEvAve2xyrhvxN5h9NWnfxozSuyiTeBFkvn hub
Who may write: anyone, from any peer. A public project would also
charge proof-of-work per letter (hbs2-hub policy pow).
$ hbs2-hub policy default --mailbox $MBOX --sender allow --peer allow
policy written
policy version 1
(peer allow all)\u{0a}(sender allow all)\u{0a}
$ hbs2-cli hbs2:sigil:create:from-keyring ~/mailbox.key > ~/mailbox.sigil
Now write both into the repository, so a contributor needs nothing but
the repo key:
$ hbs2-git3 repo:mailbox:set $REPO --key $MBOX
declared (mailbox 6kc1AzwUCeEvAve2xyrhvxN5h9NWnfxozSuyiTeBFkvn hub)
$ hbs2-git3 repo:mailbox:sigil $REPO --key $MBOX --sigil $MBOX_SIGIL
published sigil HzNxqet6C1V6KpvXt2f2TQHJz5J7TXwznpPDjCdskvCC
$ hbs2-hub status --repo $REPO
repository 7gGDvjZ6x4Dvq2DuK1FRLsRnpmjnge94wyMKozyxb6wi
signing yes: this machine holds the repository key
canon    none here yet
published nothing to publish
mailbox 6kc1AzwUCeEvAve2xyrhvxN5h9NWnfxozSuyiTeBFkvn
         nothing waiting

== 4. A contributor clones it ==

[contrib]
All they were given is the repo key.
$ git clone -q hbs23://$REPO project
use git fetch to get latest versions
To write letters they need an identity (a keyring), its sigil (so the
owner can answer them) and a mailbox for the answers.
$ mkdir -p ~/.hbs2-keyman/keys && hbs2-cli hbs2:keyring:new > ~/.hbs2-keyman/keys/me.key && hbs2-keyman update
$ hbs2-cli hbs2:sigil:create:from-keyring ~/.hbs2-keyman/keys/me.key > ~/me.sigil
$ hbs2-peer mailbox create --key $ME hub
created BMnJ8NQTnQbtmevV15gUUWoh6ArZAtqchLoGRrp7B5Ls hub
$ hbs2-hub whoami --author $ME --sender $ME_SIGIL --repo $REPO
author BMnJ8NQTnQbtmevV15gUUWoh6ArZAtqchLoGRrp7B5Ls : this machine can sign as it
sender 7RZLTE6JQh68kVEjpDgbW4qvdZawRU6yUU7H2hMADoyC : names BMnJ8NQTnQbtmevV15gUUWoh6ArZAtqchLoGRrp7B5Ls
the sigil names that key: a reply can reach you
repo 7gGDvjZ6x4Dvq2DuK1FRLsRnpmjnge94wyMKozyxb6wi : mailbox 6kc1AzwUCeEvAve2xyrhvxN5h9NWnfxozSuyiTeBFkvn
  recipient sigil HzNxqet6C1V6KpvXt2f2TQHJz5J7TXwznpPDjCdskvCC
The repository names the sigil to seal letters to; fetch it once.
$ hbs2-peer fetch $PROJECT_SIGIL

== 5. The contributor files an issue ==
$ echo "greet.sh prints \"Helo\" instead of \"Hello\"." | hbs2-hub issue new --repo $REPO --author $ME --sender $ME_SIGIL --title "Typo in the greeting" --body -
hbs2-hub: solving 18 bits of work to leave this peer
queued 2uAVPj8VEHoR1Sk6gSctpf8ujgxPYmii2XivvJPDGRhr
thread ERduLUPV38Sq5n8QEaCuELzNpsxvayn7iskZ8jvdwxCK
the peer has it, and nothing is in canon until a maintainer folds it;
  `hbs2-hub updates --repo <key> --mailbox <your-mailbox>` is what comes back.

== 7. The owner accepts the issue ==
Accepting folds the letter into canon: the project's signed,
append-only record, kept in the repository under refs/hbs2/meta.
$ hbs2-hub inbox accept --repo $REPO --message $ISSUE_MSG

  `hbs2-hub publish` sends it, and until it does no clone sees it.
("no acknowledgement" is expected here: the repository key made by
repo:init has no encryption key to seal a reply with. The record does
not depend on acks; the contributor reads canon itself.)

== 9. The contributor sends a fix ==
A pull request is a git bundle of the new commits, sealed into a letter
the same way. Only the delta travels.
$ git checkout -qb fix-typo && sed -i "s/Helo/Hello/" greet.sh && git commit -qam "greet: fix the typo"
$ hbs2-hub pr new --repo $REPO --author $ME --sender $ME_SIGIL --title "Fix the greeting typo" --onto master --from fix-typo --body "Fixes #1."
